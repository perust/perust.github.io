이번 주에는 『혼자 공부하는 바이브 코딩 with 클로드 코드』 Ch 03을 공부하고, 손글씨로 쓴 숫자를 인식하는 프로그램을 만들었습니다. 3주차 기본 미션은 PROJECT 3의 데스크톱 프로그램을 완성하고 실행 화면을 캡처하는 것이었고, 추가 미션인 웹 버전도 함께 만들어 확인했습니다.

앞선 1-2주차에는 아티팩트로 웹페이지를 만들며 프롬프트와 PRD를 배웠다면, 이번에는 Claude Code가 실제 코드를 작성하고 프로그램을 실행하는 흐름을 경험했습니다. 화면 안에서 결과를 미리 보는 데서 한 단계 더 나아가, 로컬에서 실행되는 작은 프로그램을 만드는 과정이었습니다.

## Claude Code에 요청한 내용

처음에는 원하는 기능을 한 문장으로 요청했습니다.

> 손글씨로 숫자를 입력하면 이것을 인식하는 코드를 만들어서 실행해 줘. 모든 코드와 주석을 영어로 작성해 줘.

![Claude Code에 손글씨 숫자 인식 프로그램 제작을 요청한 화면](/images/posts/2026-07-26-vibe-coding-week3/01-prompt.webp)

요청 자체는 짧았지만 결과물에는 여러 요소가 필요했습니다. 숫자를 그릴 캔버스, 인식과 초기화 버튼, 예측 결과를 보여주는 영역, 실제 숫자를 분류하는 모델이 하나의 흐름으로 연결되어야 했습니다. 단순히 화면만 그리는 작업이 아니라 사용자의 입력을 받아 전처리하고, 모델의 결과를 다시 화면에 표시하는 작은 애플리케이션이었습니다.

Claude Code가 코드를 생성하는 동안에는 `Transmuting...` 상태가 표시됐습니다. 코드와 주석을 영어로 작성해 달라는 조건도 함께 전달했기 때문에, 기능 요구와 코드 작성 규칙을 한 번에 지정할 수 있었습니다.

## 데스크톱 프로그램 실행

먼저 로컬에서 실행되는 데스크톱 버전을 확인했습니다. 화면에는 `Handwritten Digit Recognition` 제목과 검은색 입력 캔버스, `Recognize`, `Clear` 버튼, 예측 결과 영역이 배치됐습니다.

![손글씨 인식 데스크톱 프로그램의 초기 화면](/images/posts/2026-07-26-vibe-coding-week3/02-desktop-initial.webp)

초기 화면이 정상적으로 뜬 뒤 캔버스에 숫자 6을 직접 그렸습니다. `Recognize` 버튼을 누르자 아래의 Prediction Result 영역에 6이 표시됐습니다.

![직접 쓴 숫자 6을 정확하게 인식한 데스크톱 프로그램](/images/posts/2026-07-26-vibe-coding-week3/03-desktop-six.webp)

손으로 쓴 숫자는 사람마다 모양과 굵기가 다르고, 같은 사람이 써도 매번 달라집니다. 제가 그린 6도 인쇄된 글꼴처럼 반듯하지 않았지만 프로그램은 숫자를 제대로 구분했습니다. 버튼을 눌렀을 때 결과가 바로 나타나니 코드만 읽을 때보다 전체 동작을 훨씬 쉽게 이해할 수 있었습니다.

`Clear` 버튼은 입력한 그림과 결과를 지우고 다시 시도할 수 있게 해줍니다. 작은 기능이지만 입력, 실행, 결과 확인, 초기화라는 프로그램의 기본 흐름을 갖추는 데 꼭 필요한 요소였습니다.

## 웹 버전 결과

추가 미션에서는 같은 손글씨 인식 기능을 웹 형태로 확인했습니다. 검은 캔버스에 숫자 5를 쓴 뒤 `Recognize` 버튼을 누르자 Prediction Result에 5가 표시됐고, Confidence는 96.0%였습니다.

![웹 버전에서 손글씨 숫자 5를 96.0% 신뢰도로 인식한 결과](/images/posts/2026-07-26-vibe-coding-week3/04-web-five.webp)

데스크톱과 웹 버전의 핵심 기능은 같지만 결과물을 보여주는 방식은 달랐습니다. 데스크톱 버전은 별도의 프로그램 창에서 실행됐고, 웹 버전은 브라우저에서 보기 좋은 세로형 화면으로 구성됐습니다. 같은 아이디어라도 실행 환경에 따라 인터페이스와 배포 방식이 달라질 수 있다는 점을 결과 화면으로 비교할 수 있었습니다.

또한 웹 버전에는 숫자 결과뿐 아니라 신뢰도도 함께 표시됐습니다. 모델이 5라고 답하는 것과 5일 가능성을 96.0%로 계산하는 것은 다른 정보입니다. 이번 실습을 통해 AI의 출력은 정답 하나만 보여주는 것이 아니라, 예측에 대한 확률이나 신뢰도를 함께 다룰 수 있다는 점도 자연스럽게 확인했습니다.

## 이번 주에 배운 점

이번 실습에서 가장 크게 느낀 점은 바이브 코딩이 화면을 빠르게 만드는 데서 끝나지 않는다는 것이었습니다. 한 문장으로 프로그램 제작을 요청할 수는 있지만, 실제로 완성됐다고 말하려면 프로그램을 실행하고 직접 숫자를 그려보고 버튼과 결과가 제대로 연결되는지 확인해야 합니다.

특히 손글씨 인식 프로그램은 입력과 출력이 눈에 보여서 검증하기 좋았습니다. 캔버스가 열리는지, 마우스로 선을 그릴 수 있는지, Recognize 버튼이 동작하는지, 예상한 숫자가 표시되는지, Clear 버튼으로 다시 시작할 수 있는지를 순서대로 확인할 수 있었습니다. AI가 코드를 만들어줬다는 사실보다 제가 직접 실행해보고 결과를 확인했다는 과정이 더 중요하게 느껴졌습니다.

데스크톱 버전과 웹 버전을 연달아 만들어본 것도 의미가 있었습니다. 핵심 로직이 같아도 사용자에게 제공되는 형태는 달라질 수 있고, 같은 기능을 다른 환경으로 옮길 때 화면 구성과 사용 흐름을 다시 생각해야 합니다. 이번에는 짧은 실습이었지만 프로그램의 입력, 처리, 출력, 인터페이스가 어떻게 이어지는지 한 번에 볼 수 있었습니다.

## 3주차 후기

1-2주차에는 원하는 결과를 얻기 위해 프롬프트를 구체적으로 쓰고 작업을 단계로 나누는 법을 배웠습니다. 3주차에는 그 방식이 실제 프로그램 제작으로 이어졌습니다. "손글씨 숫자를 인식하는 프로그램"이라는 목표를 전달하고, 생성된 코드를 실행한 뒤 숫자 5와 6으로 결과를 검증했습니다.

아직 이 실습만으로 손글씨 인식 모델의 원리나 정확도를 모두 이해했다고 할 수는 없습니다. 다만 AI 코딩 도구를 이용하면 아이디어를 실행 가능한 형태로 빠르게 옮기고, 직접 조작하면서 배울 수 있다는 점은 분명했습니다. 코드 생성으로 끝내지 않고 실제 입력을 넣어 결과를 확인하는 습관이 바이브 코딩에서도 중요하다는 것을 배운 3주차였습니다.
