벌써 6주 챌린지를 완료하고 완독 후기를 남기게 되었다. 원래가 코딩을 하던 개발자가 아니다 보니 AI를 활용한 바이브코딩이라도 어려움을 많이 느꼈고, 그렇게 해서 계속 관심을 가지게 된 것 같다.

먼저 1장부터 8장까지 읽은 내용을 아주 짧게 정리하고, 그다음에 이번 챌린지를 하면서 느낀 것들을 적어보려고 한다.

## 1장부터 8장까지, 아주 짧게 정리하면

### 1장

바이브 코딩이 무엇인지, AI 코딩 도구에는 어떤 유형이 있는지 보고 클로드 아티팩트로 첫 웹페이지를 만들어봤다. 한 번에 완성품을 받아내는 방식이 아니라, 나온 결과를 눈으로 보고 다시 고쳐 달라고 요청하며 쌓아가는 방식이었다.

### 2장

좋은 프롬프트의 조건은 명확성, 구체성, 맥락 제공이었다. 막연한 아이디어는 5W1H와 PRD로 정리하고, 만들 때는 뼈대, 기능, 디자인, 점검 순서로 나눠서 요청하는 편이 훨씬 나았다.

### 3장

손글씨 숫자를 인식하는 프로그램을 만들면서, 클로드 코드가 필요한 환경을 먼저 확인하고 MNIST 학습까지 이어가는 과정을 봤다. 그래도 마지막에 앱을 직접 실행해서 숫자가 제대로 인식되는지 확인하는 건 내가 할 일이었다.

### 4장

PRD를 단계별 프롬프트로 바꿔서 할 일 관리 앱을 만들었다. 프로젝트가 커질수록 긴 내용을 대화창에 다시 붙여넣기보다, 문서를 파일로 남겨두고 AI가 그 파일을 직접 읽게 하는 쪽이 확실했다.

### 5장

퀴즈 게임을 만들면서 할루시네이션을 줄이는 규칙과 반복 작업을 커스텀 명령어로 묶는 방법을 봤다. 자동화를 해도 정답의 기준과 검증 절차는 사람이 미리 정해둬야 한다는 게 남았다.

### 6장

외부 AI API를 붙이는 장인데, 어떤 모델을 고르느냐보다 무료 한도와 비용, 응답이 실패했을 때의 처리가 먼저 걸리는 문제였다. API 키는 코드에 그대로 두지 않고 별도 파일로 분리해서 보관해야 했다.

### 7장

코드 리뷰, 성능, UX, 백엔드, QA처럼 역할을 나눈 서브 에이전트를 만들어 개발팀처럼 일을 넘기게 했다. 다만 에이전트가 다 됐다고 보고해도 실제 결과물을 열어서 내가 정한 기준으로 다시 확인해야 했다.

### 8장

MCP로 도구를 연결하고 테스트, 버전 관리, 배포, 데이터베이스까지 이어보는 마지막 장이었다. 연결하는 일이 쉬워진 만큼, 붙인 다음에 계속 책임질 수 있는지가 더 큰 질문으로 남았다.

## 이번 챌린지를 신청한 이유

다른 일을 할 때에 개발자에 대한 욕망이 있어서 계속 기웃기웃했지만, 원체 공부를 시작하는 장벽이 높게 느껴졌던지라 시작을 하더라도 제대로 끝맺지 못하고 그냥 흐지부지 그만두게 됐었다.

혼공 학습단을 통해서 쉬운 것부터 시작해보자 했어도 책을 시작부터 끝까지 온전하게 집중해서 하기가 어려웠다. 직장을 다니면서 에너지를 쏟을 여력이 없기도 했지만, 애초에 그렇게 공부를 꾸준히 하는 타입이 아니었기 때문에 끈기 있게 끝까지 밀고 나가지는 못했던 것 같다.

혼공 학습단을 하더라도 처음 2-3주차까지는 꼼꼼하게 하다가 4주차즈음이 되면 내용도 어려워지고, 점점 책을 휙휙 넘기며 실습을 완료하고 인증하는 데에만 급급하게 된다.

그렇게 몇 번의 혼공학습단을 하다 보니 끝냈던 책을 다시 해도 내용이 기억나지가 않고 도무지 머릿속에 남아있질 않았지만, 그래도 2-3주차까지 했으면 다음에 할 땐 3주차까지는 덜 힘들고 4주차까지 잘 할 수 있겠지라는 생각으로 혼공 학습단을 계속 신청하려고 했던 것 같다. 한창 바쁠 때는 도저히 안 될 것 같아 쉬었더니, 그러면 또 계속 쉬게 되었다.

이번에 바이브코딩이 확 뜨게 되었고 수많은 바이브코딩 책들이 나오게 되었는데, 혼공학습단도 때마침 바이브코딩 책으로 인프런 챌린지가 나오게 되어 조금은 설레는 마음으로 신청을 했었던 것 같다.

## 배우면서 실제로 해본 것

이 책도 처음 1차 챌린지를 할 때 신청을 했었는데, 그때가 처음 바이브코딩 해본다고 혼공학습단 인프런챌린지를 통해 처음 시도해볼 때라 정말 신기하고 신세계를 맛본 기분으로 책을 따라했었다. 그렇게 신나게 했는데도 4주차 정도 되면서 또다시 급하게 미션을 했었던 기억이 난다.

그래도 책을 통해서 바이브코딩을 배우면서 회사에서 업무에 많이 활용했었고, 개인적인 능률이나 성과에도 꽤 좋은 효과를 가져왔었다. 그렇게 업무보조 프로그램도 만들어보면서 동료들에게 공유하기도 하고, 친구들한테 알려주기도 했었다.

이전에는 회사의 오래된 선배들이 프로그래밍을 해서 만들었던 프로그램을 사용하고, 그 선배들이 퇴사해서 유지보수가 안 되는 프로그램을 사용하며 다들 나름대로 적응하면서 업무에 최대한 활용하려고 했었는데, 바이브코딩을 하고 나니 그 프로그램을 쓸 필요가 없이 내가 만들어서 필요한 기능을 넣고 유지보수를 하며 사용하니 능률도 크게 올랐었다. 그리고 회사의 잡다한 반복 작업을 자동화시킨 프로그램을 만들어, 몇 분은 확인하고 옮기는 작업을 버튼 몇 번으로 완료하게 만들어버리니 시간 단축도 크게 되고, 그런 것들이 너무 재미있었던 것 같다.

## 모델이 좋아질수록 더 크게 보인 것

이제는 모델들도 많이 좋아지고 바이브 코딩을 할 수 있는 범위도 꽤 넓어졌는데, 오히려 그럴수록 개발자의 역량이 더 중요하게 느껴진다. 처음 바이브 코딩을 하면서 어디까지 만들 수 있는지 이것저것 만들어보고 어린애가 장난감 다루듯이 가지고 놀았다면, 지금은 그 이후의 작업까지 생각해보니 결코 쉬운 것이 아님을 점점 더 뼈저리게 느끼고 있는 것 같다. 데이터베이스를 연결하고, 서버에 올리고, 보안에 신경 쓰고, 메모리나 스토리지, 데이터 보안, 병목, API 등등 신경 쓸 게 너무 많아, 이제는 출시는 도저히 못 할 것 같은데? 라는 생각이 들기도 한다.

그러면서도 한창 바이럴되고 뜨는 바이브코딩으로 만든 서비스들을 보면, 와 저렇게 만들 수도 있구나 라는 생각이 들기도 한다.

그런 한계점들을 느끼면서 이번 인프런챌린지를 신청한 것 같다. 내가 한번 학습할 때 끝까지 꾸준히 집중해서 못하더라도 10%라도 얻어가면 좋지 않을까, 그냥 눈에라도 익으면 좋지 않을까, 모르는 거 조금 실습해서 손에라도 조금 익숙해지면 조금이라도 나아지지 않을까, 조금이라도 봐놓으면 다음에 조금이라도 도움이 되겠지 라는 생각으로 이번 바이브코딩 챌린지에 신청하게 되었다.

## 이번에는 조금 다르게 해봤다

이번에는 정리를 하는 것도 하지만, 개념 정리를 하는 것에 집중하는 것이 아니라 책을 일단 읽어보는 것에 더 중점을 뒀다. 개념들을 하나하나 정리를 하면서 시간 소비가 많이 되는 것 같아, 개념들을 전부 정리하는 것이 아니라 정말 간단하게 요약하면서 최대한 책을 읽는 것에 집중했다.

읽어보고 실습을 하며, 실습 프롬프트대로 하고 끝이 아니라 뭔가 좀 더 서비스같은 프로그램을 만들려고 했던 것 같다. 퀴즈 프로그램을 실제 캐릭터가 뛰어다니며 움직이는 퀴즈 게임으로 만들어보고, 온라인 메뉴도 만들어서 방을 만들고 참여하는 흐름까지 생각해보기도 했다.
